# 设计与方案复核记录

日期：2026-10-14。范围：现有全部方案文档、新增 UI/开发规范、设计参考页和 guard skill。当前是设计阶段；本文不构成 Go/Swift 实现、HIG 运行验证、模型质量、Apple 审核或法律许可通过记录。

## 修订结论

通用个人信息工作台、开源极客先推广、先纯开源、Go 服务端 + Swift macOS 首期的边界保持一致。主界面现为无导航侧栏的“资讯”工作台：默认全部内容，筛选并入标题栏，设置保持单一入口。桌面内容列表与详情并列，手机列表进入详情；两端共用亮暗主题与筛选语义。v0.5 进一步移除装饰性 indicator、拼接式元信息与模板化文案，通过排版和对齐保持层级。页面状态、数据契约与验收已相互对齐。v0.6 按用户最后确认将主入口命名为“资讯”、合并筛选与标题栏，作为后续实现基线。方案可作为 M0 实施起点；仍需用正式 OpenAPI、原生组件和真实样本验证设计假设。

## 关键实现修正

1. **提交序号不能等同数据库 sequence。** 较低序号事务后提交，会被已经前进的游标跳过。设计采用账户内短事务序列锁与一致 snapshot；M1 必须用乱序提交证明不会遗漏。
2. **删除必须约束后台旧任务。** 除 tombstone，还需发布/写回时检查删除代际；发往外部的在途请求不能承诺瞬间撤回。
3. **页面需要持久状态。** 收藏、阅读状态、反馈处理和偏好草稿都要协议支持；离线与服务端应用状态区分，不能凭动画显示成功。
4. **一般信息不应被强制当新闻。** 观点、私人安排、资料和创作保留其性质；求真深度按内容与用户设置决定，但不能隐藏已知矛盾或伪造证实。
5. **原生设计与远程正文分工清楚。** 模板支持个性化排版，客户端持有导航、操作、权限和证据状态；浏览器参考页不成为 App Web UI 实现承诺。

## 无侧栏、筛选与跨平台修订

v0.4 确立以下交互结构；v0.5 沿用该结构；v0.6 仅调整主入口名称与筛选位置，数值 token 仍为 v4。默认“全部”阅读工作台取代“今日”根栏目；今天/昨天仅为时间分组。全部/未读/收藏为互斥视图，分类/标签/关注/时间和搜索共同过滤。设置集中到一个入口，包含兴趣、来源、外观、通知、反馈、账户与数据；桌面和手机都不再设导航侧栏或“今日/收藏”底部栏目。原生菜单和 Command-comma 指向同一设置场景。

桌面保留内容列表 + 详情两块内容窗格；窄窗和手机使用列表进入详情。浅色暖纸白、深色暖炭灰不变，两个平台使用同一主题 token。已更新六张主视觉记录，并增加筛选与设置面板记录。

以下是 v0.4 的交互复核记录，v0.5 的改动与重新检查见后节。

| v0.4 浏览器场景 | 实际结果 |
| --- | --- |
| 全部 / 未读 / 收藏 | 初始样例分别 5 / 3 / 2 条；筛选不自动改已读或偏好 |
| 收藏 + 阅读标签 | 2 条；原先摄影内容被排除后，详情显示选择提示，没有跳到另一条 |
| 生活分类 + 阅读标签 | 0 条，显示“没有匹配的内容”；与来源没有更新区分 |
| 搜索城市后清除筛选 | 搜索词保留，返回 2 条；搜索与筛选独立清除 |
| 关注城市漫步 | 2 条，并显示“立即获取”；点击明确提示仅设计演示，未触发真实采集 |
| 今天 + 阅读标签 | 1 条；进入详情再返回，两个条件与所选行保留 |
| 收藏视图取消收藏 | 结果由 2 变 1，详情进入选择提示；离线标明缓存范围 |
| 历史内容返回 | 手机打开末行再返回后，列表保留非零滚动位置（约 267.5 CSS px） |
| 统一设置 | 一个主入口可切换六个分组；外观分组切换深色后整页同步变化。其余设置为说明性布局 |
| 窄窗 / 大字号 | 680 宽桌面、200% 正文为 32 CSS px，阅读区 clientWidth = scrollWidth = 678；390 宽手机、200% 为 34 CSS px，宽度均为 388，无横向溢出 |
| 对齐 / 操作尺寸 | 桌面 5 条样例行高均约 124.5 CSS px，文字左边线一致；详情标题/正文/依据/操作区左边线一致。手机行高约 133.7 CSS px；筛选、设置、返回、收藏、反馈及筛选弹窗控件高均为 44 CSS px |

上述测量使用 1280×900 浏览器 viewport；手机参考容器为 390×844 CSS px。相等样例行高是该内容与字号下的观察，长标题/辅助字号允许自然增高。参考页的阅读缩放不是 iOS Dynamic Type，不覆盖真实安全区、VoiceOver、系统强调色和原生窗口行为。

参考页在本地内存过滤虚构样例；各维度演示单选，原生契约支持多选。静态设置、导入、真实查询分页/取消、后台采集和撤销等完整能力仍按里程碑实现；不把演示行为当作服务端验收。之前版本已检查依据展开与反馈语义，本轮重点验证新布局和筛选链路。捕获日志未见 error/warn。

## 排版与信息克制修订 v0.5

用户要求避免 AI slop，具体指出 indicator 和圆点分割文本。本轮去掉未读圆点、列表收藏徽标、井号标签、重复内容类型眉题、筛选按钮外框及参考页的宣传标题/编号功能块。分类和时间使用左右对齐的独立字段；详情单独呈现更新时间与来源说明，分类/标签移至正文后的内容信息区。标签仍能点击筛选，未读标题采用较强字重并保留辅助功能状态。

设置中的关注主题改为逐项排列，离线提示改为完整短句。搜索、设置、展开、返回等有明确作用的图标保留。浏览器参考页移除模拟的窗口圆点，原生 App 的系统窗口控制仍按 HIG 保留。没有对源内容标点或有意义的 Markdown 列表施加全局禁令。

已重新查看桌面/手机的浅色与深色四种组合，更新本页全部八张视觉记录。正文后“摄影”标签筛选返回 1 条，叠加收藏为 0 条并显示空结果；加入收藏后收藏视图为 3 条，详情动作显示“已收藏”。手机筛选“阅读”返回 2 条，选中条件以“标签：阅读”呈现，不再拼接一排元信息。设置关注主题的独立行也在浏览器中确认。

200% 阅读字号下，390 宽手机正文为 34 CSS px，阅读区 clientWidth/scrollWidth 都为 388；680 宽桌面正文为 32 CSS px，两项宽度都为 678。手机正文后的分类/标签操作区均为 44×44 CSS px。捕获日志未见 error/warn。此轮不重复证明原生 VoiceOver、iOS Dynamic Type 或服务端查询，仍为浏览器设计证据。

UI 规范、Apple 客户端、开发规范、索引、决策和 guard 已同步。静态检查继续验证本地引用、JSON、22 组候选配色及 token 一致性；没有把“美观”改写成字符黑名单测试，最终以具体画面和交互观察判断。

## 资讯命名与标题栏合并 v0.6

按用户最终调整，主入口从“阅读”改为“资讯”，将全部/未读/收藏与分类/标签/关注整合进标题栏，移除单独的筛选行。宽窗展示完整控件，窄窗将分类等收进“筛选”，手机进一步采用资讯视图菜单与搜索按钮。设置继续只有一个入口，原生实现保留系统窗口控制和拖动空间；此次调整没有改变通用内容范围或 API。

当前八张截图均更新为 v0.6。1280×900 浏览器 viewport 下，1120 宽桌面标题栏高 64 CSS px；680 窄窗仍为 64；390 手机为 65，均无横向溢出。手机视图菜单、筛选、搜索和设置的操作区高度均为 44 CSS px，宽度至少 44。独立筛选条已不占正文空间，只有有效筛选条件及清除/获取动作按需显示在结果区。

手机通过“收藏资讯”菜单配合阅读标签得到 2 条；搜索“街道”后收窄为 1 条，进入详情并返回保留标签和搜索。桌面/手机亮暗四种组合已查看，680 窄窗和 390 手机在 200% 阅读字号下，阅读区 clientWidth/scrollWidth 分别同为 678 / 388，无横向溢出；捕获日志未见 error/warn。文档、参考页与 guard 已同步并通过静态校验。以上仍为浏览器设计证据，原生窗口/VoiceOver 验收留在实现阶段。

## Guard 的维护

仓库 canonical skill 位于 [melted-guard](../../skills/melted-guard/SKILL.md)，根目录 AGENTS 负责指向它。当前工作环境可用全局 skill symlink 指向该目录，避免两份规则漂移；其他贡献者依照仓库 AGENTS 即可使用，不依赖本机绝对路径。

skill 按任务加载对应规范，保留用户当前授权，不新增重复确认流程。静态脚本只管可确定验证的部分；原生品质和通用内容效果仍须真实观察。后续依据实际失误改进规范，不将每个个例升级成无关任务的通用限制。
