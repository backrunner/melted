# Melted UI 设计规范 v0.8

更新：2026-10-15。用户已确定：素雅、有设计感、有品质感和现代感，遵循 Apple HIG；采用更明亮、温暖、适合阅读的米白色系，不用绿色，并保持 UI 整齐。亮暗两套外观同时设计，desktop/mobile 使用统一设计语言；主界面无导航侧栏，设置集中到标题栏最右侧入口，隐藏可见“资讯”标题，全部/未读/收藏保留，分类/标签/关注合并进标题栏的统一搜索入口；避免装饰性 indicator、圆点拼接文本和模板化 AI 文案。本文是实施基线；具体色值和尺寸仍需原生窗口验证。HIG 对齐、静态预览、运行验收、App Review 是不同证据。

## 1. 视觉方向

以舒适阅读为中心。浅色以接近纸白的暖白为主，只保留极轻的暖调（2026-10-15 按用户反馈再降黄度），避免深米黄铺满界面造成发暗、发旧的感觉。暖灰区分层级，柔和褐色提示操作；品牌与自定义内容配色不使用绿色。文字、间距和对齐建立层级。信息密度适中，留白服务于分组与阅读，不用巨大标题、空洞大卡片或装饰填满窗口。

品质来自细节一致：列表基线整齐、控件状态完整、长文清晰、窗口缩放稳定、操作有及时反馈。现代感采用当前系统控件与材质，不依赖大面积渐变、发光、玻璃卡片、过量胶囊标签或反复的 AI 星光图标。

从首期支持通用内容。示例同时使用文化活动、兴趣资料和工作消息；技术内容只是其中一种。用户界面把 Subject 显示为“关注主题”，provider 显示为“处理服务”，不向普通用户暴露 pipeline、rubric 或置信度小数。

### 排版与信息克制

主界面用文字层级、留白、对齐和分组表达关系。避免装饰性 indicator、未读圆点、状态灯、AI 星光、重复徽章、井号标签串和没有操作含义的小图标。信息不足时保留空白，不补装饰。

元信息是独立字段，不把分类、时间、来源、标签、状态用 `·`、`•`、竖线或斜杠串成一行，也不用大量空格替代布局。列表只放标题、摘要、分类与时间：分类左对齐，时间右对齐；详情的更新时间、来源说明和内容信息各有明确位置。多个字段拥挤时换行或减少默认展示。

未读标题使用较强字重，已读使用常规字重；辅助功能同时播报已读/未读状态，选中仍由原生选择状态表达。收藏状态由详情动作“收藏 / 已收藏”呈现，列表不再追加重复徽标。分类/标签放在正文后的内容信息区，用短标签和可识别的文字操作，分类采用轻量米色胶囊，标签不默认加井号。

标题直接说明内容，避免每篇重复“安排更新/资料整理”等眉题、编号栏目和通用三段式介绍；界面文案只说明实际状态、动作及必要原因。设计参考页本身也不堆叠宣传标题与功能卡片。

功能性图标按实际用途保留，例如搜索、设置、菜单展开和返回。真实加载、错误和证据缺口必须清楚表达；原生窗口控制、焦点和可访问状态照常保留。此约束针对 App 装饰及元信息排版，不禁止正文中有意义的 Markdown 列表、原文标点或必要的系统控件。

## 2. HIG 对齐与平台适配

| 一手依据 | Melted 的设计决定 |
| --- | --- |
| [Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：材质表达层级，Liquid Glass 用于导航/控件层，避免用于正文层 | 优先系统 toolbar、菜单和 popover；正文使用稳定阅读底色。新系统由原生组件采用系统外观，旧系统用其标准材质，不自行模拟新系统玻璃 |
| [Typography](https://developer.apple.com/design/human-interface-guidelines/typography)：系统文字样式、可读性及平台差异 | 系统字体及中文 fallback，阅读字号可调；iOS 采用 Dynamic Type，macOS 单独提供阅读缩放 |
| [Color](https://developer.apple.com/design/human-interface-guidelines/color)：支持深浅色、增强对比和语义颜色 | 控件、选中、焦点优先系统颜色；自定义颜色提供主题变体并测实际对比 |
| [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)、[Windows](https://developer.apple.com/design/human-interface-guidelines/windows) | 保留原生标题栏、交通灯、拖动和缩放；遵守 safe area，窄窗按任务折叠栏位 |
| [Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars) | 保留系统 toolbar、搜索、菜单与溢出行为；主界面采用内容列表/详情，没有常驻导航侧栏 |
| [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)、[Motion](https://developer.apple.com/design/human-interface-guidelines/motion) | 全键盘、VoiceOver、Reduce Motion/Transparency、Increase Contrast；状态不用颜色独自表达，动画短且有因果关系 |

资料查阅于 2026-10-14；部分 Apple 页面通过官方文档 JSON 读取。实施依赖新 API 时核查 SDK availability，保留最低支持系统路径。不能因为当前 HIG 展示新外观，就把 macOS 14/iOS 17 候选最低版本悄悄提高。

## 3. Token 与字体

[design/tokens.json](design/tokens.json) 是自定义设计 token 的单一数值来源；[设计参考页](design/reference.html)用于比较深浅色、布局与状态。参考页是浏览器设计示意，不是原生 App，也不能用于证明 HIG 或运行验收通过。

### 色彩

原生控件使用系统 label、secondaryLabel、separator、controlAccentColor、选中和焦点语义；macOS 尊重用户主动选择的系统强调色。Melted 默认品牌强调色使用低饱和褐色；正文是明亮暖纸白，列表与筛选区域只略深，选中行用淡米沙色。深色采用暖炭灰环境、略亮阅读面、柔和米白文字与淡褐强调色，保留层次，避免纯黑压暗或整屏泛黄。颜色层次要轻，不加纸张纹理、仿旧噪点或强黄滤镜。

| 语义 | 浅色候选 | 深色候选 | 用途 |
| --- | --- | --- | --- |
| canvas | `#F7F6F3` | `#232220` | 轻暖阅读环境，不强制覆盖原生导航材质 |
| surface | `#FDFDFB` | `#2C2A27` | 明亮暖纸白 / 略亮的深色正文面 |
| text | `#2F2B27` | `#F1EBE0` | 正文、标题 |
| secondary | `#66605A` | `#BFB5A7` | 时间、来源说明；不能淡到难以阅读 |
| accent | `#79603F` | `#D6BA92` | 少量主要操作和链接；使用时满足对比 |
| selection | `#EDEAE4` | `#403A32` | 自定义阅读列表参考，原生选中交给系统 |

默认跟随系统外观，可在 App 设置选择跟随系统/浅色/深色；选择保存在设备端，不随内容或模板改变。两种模式分别配置语义色，禁止用 CSS/图像反相实现深色。切换保留阅读位置、选择和未提交输入；图片保持原色，透明图、表格、代码、附件占位、sheet 和错误状态都检查双主题。

警告和错误使用有文字/图标的语义状态；普通“依据有限”不做强烈报警。separator 仅作装饰分隔，不承担输入框或焦点等必要识别功能。

自定义正文和辅助文本采用至少 4.5:1 的项目目标，大字号文本至少 3:1；关键自定义边界/焦点至少 3:1。正文始终按 4.5:1 检查，避免用字号例外降低阅读质量。玻璃/图片上的颜色必须在实际背景检查，静态 hex 对比不能证明这些场景通过。增强对比时回到更明确的系统语义或专门变体。

### 文字和间距

| 层级 | macOS 初始值 | iOS 方向 |
| --- | --- | --- |
| 详情标题 | 24 pt，semibold，允许多行 | title2/title，随 Dynamic Type |
| 内容分节 | 17 pt，medium/semibold | headline |
| 阅读正文 | 16 pt，regular，用户可缩放 100–200% | body 默认系统大小，支持全部辅助字号 |
| 列表标题 | 14 pt，medium | body/headline |
| 操作/表单 | 系统 regular control size，通常 13 pt | 系统标准控件 |
| 时间/辅助信息 | 12 pt，regular | footnote/caption，保持可读 |

使用系统字体，中文交给系统 fallback，代码才用等宽。长正文不使用全局细体、不逐字增加字距；必要行距由阅读组件统一控制。HTML 初始行高 1.7；SwiftUI/AppKit 对应值按真实排版校准，不机械复制 CSS。

间距基元：4、8、12、16、24、32、48 pt；16/24 是主要内边距，8 是同组控件间隔。系统控件内边距不强改以凑格点。自定义阅读行圆角 8、内容面 12 pt；原生按钮、popover、sheet 的圆角交给系统。正文结构用间距/细分隔，阴影只用于实际浮层。

## 4. macOS 布局

主界面命名“资讯”，默认查看全部已整理内容，按最近更新时间排列；“今天/昨天/更早”只是列表内的时间分组。每日简报仍是一种内容，不把产品入口限定成“今日”。不设置常驻导航侧栏。“资讯”是界面名称，仍承载通用资料、消息和私人内容，不将领域改成仅新闻。用户已认可此方向作为后续实现基线。

初始窗口建议 1120×760 pt，候选最小 680×520 pt；这不是 Apple 规定。桌面正文区为内容列表 + 阅读详情两栏，列表理想 320 pt、可在 280–360 pt 调整；阅读宽度优先保持约 480 pt，最大约 720 pt。约 860 pt 以下或大字号导致空间不足时，改为列表/详情前后导航；没有第三栏。分隔条属于内容窗格，不承载导航菜单。

把全部/未读/收藏、分类/标签/关注与搜索集成到同一条原生标题栏 toolbar，移除独立筛选行。保留一个“设置”入口；导入及低频操作使用 toolbar 溢出菜单或原生菜单命令。原生交通灯、拖动区域、最小点击区与键盘访问优先，不靠压缩到难以点击来强塞控件。

标题栏单行保留全部/未读/收藏，右侧是“搜索与筛选”和最右设置。空间不足时快捷视图变为菜单，搜索入口缩短；不保留“资讯”文字标题或独立分类下拉。⌘F 打开 Spotlight 式面板：同一输入框搜索正文和 taxonomy，可输入“分类:文化”“标签:阅读”“关注:周末”，选择后作为可移除条件保留；文本与各条件取交集。上下键选建议，Return 选择或查看结果，Escape 关闭。手机沿用同一语义，使用平台原生搜索 sheet 与 44 pt 操作区；当前仅实现 macOS。

分类胶囊采用现有 selection 填色、secondary 文字、separator 细描边，12 pt medium、水平 8 / 垂直 4 pt 内边距；不新增彩色状态或装饰圆点。空态短提示不加末尾句号。

设置入口打开同一个设置容器，按“兴趣与偏好、来源与整理、外观、通知、反馈记录、账户与数据”组织，包含服务器、渠道、导出/删除和关注主题计划管理。macOS Command-comma 和应用菜单指向同一 Settings 场景；手机使用可返回的设置页/sheet。不把来源、偏好、反馈记录分别摆在主界面边缘。

### 内容筛选

| 入口 | 作用 | 交互 |
| --- | --- | --- |
| 全部 / 未读 / 收藏 | 三个互斥的快捷视图，初始“全部” | 标题栏内的分段选择；紧凑布局用视图菜单，切换保留搜索与其他筛选，不复制内容 |
| 分类 | 宽泛内容类别，如生活、资料、工作 | 来自服务器可配置 taxonomy；不限定技术主题 |
| 标签 | 更细的主题，如摄影、城市、阅读 | 桌面 popover、手机 sheet 内选择；摘要显示已选内容与数量 |
| 关注 | 用户已定义的持续关注主题（Subject） | 过滤主题关联内容，不等于新增订阅或自动修改兴趣；尚无主题时引导至设置 |
| 时间 | 全部时间、今天、近 7 天等 | 放进筛选面板；“今天”不再是唯一主入口 |
| 搜索 | 查询整理后的标题/正文 | 与筛选共同作用；清除搜索保留筛选；Command-F 打开统一搜索面板 |

快捷视图之间互斥；分类、标签、关注、时间与搜索之间取交集，每个多选维度内部取并集，默认“全部时间”。显示当前条件和“清除筛选”，清除恢复“全部”、不限分类/标签/关注/时间，搜索框由自己的清除按钮处理。初期参考页演示单选分类/标签/关注，正式契约支持多选，不将过滤结果解释成新偏好。

用户选中具体关注主题后，可在结果摘要中“立即获取”；这是内容获取动作。目标、来源范围、定时和偏好的配置统一到设置中的“兴趣与偏好”。“收藏”通过详情书签操作及顶部快捷视图访问；分类/标签名在正文后的内容信息区可见，可点选为筛选；列表仅显示分类，避免多条标签占据阅读空间。

列表保留分页或有界加载，不为无限滚动优化停留时间。标题 1–2 行、摘要最多 2 行、分类和时间以独立字段对齐；重要内容在详情完整呈现。选中不自动等于已读，新输入不抢阅读位置。主动筛选排除当前内容时，详情进入“选择一条内容开始阅读”；空结果明确显示“没有匹配的内容”和清除筛选，不能显示成来源无更新。手机筛选只在根列表呈现，阅读详情提供返回原筛选及滚动位置。

### 整齐性规则

- 每个栏位建立固定内容边线：筛选控件共用高度和文字基线；列表标题、行标题、摘要和元信息共用左边线；详情标题、正文、依据和反馈共用正文边线。toolbar 内容与对应栏位边线协调，原生控件按实际光学边缘校准。
- toolbar 与筛选图标使用同一套 SF Symbols、统一 symbol size/weight 和等宽槽；不混用 emoji、任意字符和不同粗细图标。筛选控件数量多时收进面板，不挤压正文或增加侧栏。
- 同类列表行共用标题/摘要/元信息的排列及间距。标题最多两行，常规密度为两行摘要保留一致空间；使用共同的行内间距和最小高度，避免为了等高在短标题下堆积留白。长标题和辅助字号时按内容增长，不能固定高度裁切。
- 同组按钮共用高度、文字基线、圆角与间距；输入表单共享标签对齐和字段宽度。局部错误放在字段下方，不让旁边控件随机位移。
- 缩放和切换状态时保持选中行、正文滚动位置和对齐边线。检查浅/深色、长短标题、混排文字、空态与局部失败；禁止用空格、逐元素偏移或独立 magic number 拼出视觉对齐。

### desktop / mobile 统一规则

两端共享语义颜色、SF Symbols 图标家族、文字层级、间距基元、内容结构、状态文案与反馈含义；一个设计系统维护 Light/Dark 两套颜色，禁止 mobile 再生成一套近似色。两端使用同一筛选模型；平台尺寸、导航与输入方式分别适配。

| 维度 | 桌面 | 移动端 | 必须一致 |
| --- | --- | --- | --- |
| 导航 | 集成筛选的标题栏 + 内容列表/详情，无导航侧栏 | 标题栏视图菜单/筛选/搜索 + 根列表，详情 push；单一设置入口，无额外筛选行或底部 tab | 筛选语义、设置分组与返回保留位置 |
| 阅读 | 正文初始 16 pt，可缩放，宽度受限 | 正文 body（默认 17 pt）并支持 Dynamic Type，左右初始 20 pt、安全区自适应 | 标题、元信息、正文、依据、反馈的顺序与语义 |
| 操作 | toolbar、菜单、键盘、hover 辅助 | 最少 44 pt 触控区，关键动作始终可达，反馈用系统菜单/sheet | 动作名称、执行结果、撤销和错误说明 |
| 列表 | 中等密度，图标/文字边线固定 | 用 body 字号，行按内容与辅助字号增高；返回后不重置阅读状态 | 标题优先，摘要/时间次之；未读不等于选中 |
| 外观 | 系统材质与用户强调色 + 暖纸白/暖炭灰正文 | 同一颜色资产与正文样式，原生导航栏、sheet、safe area | 明亮温暖的浅色，层次清楚的深色，正文与状态对比 |

tokens 中 iOS pt 数值只描述默认字号参考；实际 Swift 使用对应 text style 和 Dynamic Type。自定义组件共享语义模型和 token，平台容器适配尺寸及导航。Markdown/HTML 由同一文档和主题映射生成，用户的阅读与反馈状态不因设备而改变。

四个基本设计组合（desktop light/dark、mobile light/dark）一起评审。参考页允许切换平台并复用相同样例和阅读结构；它用于检查一致性，iOS 实现仍在 P1，不把移动端示意计为原生交付。

## 5. 阅读、证据与反馈

详情结构按内容性质变化：消息显示正文和安排；资料显示整理提纲；事件变化显示新事实与背景；观点保留作者。不能给每篇内容套相同“发生了什么—对你影响”的模板。

标题和正文是视觉中心，元信息次之。正文默认不展示所有技术分数。证据入口“查看依据”可展开；影响解读的状态如“尚未确认”“存在不同说法”“内容已更正”始终可见，不能为了简洁藏进菜单。`corroborated` 的文案用“有独立佐证”，不写“绝对真实”。

详情可见“有用”“反馈…”；反馈菜单有“少看此类”“需要更多细节”“内容有误”，关键的“有误”也可在核验区域直达。明确操作立即反馈状态，离线显示“已保存在本机，联网后同步”；不能提前显示“偏好已生效”。普通可撤销操作用 Undo，不重复确认。

修改自然语言偏好采用“描述 → 预览变化 → 应用”，一次说明变化与影响，保留原文和版本。编译过程不阻塞原偏好；权限/数据去向变更才需要相应确认。删除账户等破坏性操作清楚说明对象与后果，不用红色普通按钮制造误触。

Markdown 与静态 HTML 共享颜色、字号、阅读宽度和状态组件。模板可改变正文排版，不能改变 App 导航、工具栏、证据状态或系统权限呈现。长表格可局部横滚，正文正常重排；长代码/URL不撑破窗口。已验证快照发布后整体呈现，不逐 token 流式暴露未经核验的草稿。

### 原生阅读详情精修（2026-10-15）

标题下方以一条轻量工具行放更新时间与操作：时间靠左，收藏、已读操作靠右。使用原生 borderless Button，保留文字、键盘和可访问动作，不再采用凸起按钮。每个操作至少 32 pt 高；窄处通过 ViewThatFits 重排，不缩小文字硬塞。当前年份显示月日与时间，跨年显示年份，辅助说明保留完整更新时间。标题、正文、文末内容信息保持同一左边线。

普通“无需事实核验”“有独立佐证”随文末“查看依据”显示；单一来源、尚未确认、存在不同说法、依据失效及未知状态仍出现在正文前。只有明确列出的普通状态可以下移，新增状态不能默认隐藏。收藏完成后显示“已收藏”，辅助操作名为“取消收藏”。切换内容时收起依据。

Markdown 使用结构相关的间距：分节前 28 pt、标题到正文 12 pt、段落间 16 pt，正文额外行距 6 pt；段落与列表间距随阅读缩放。二级标题为 17 pt medium，正文保持 16 pt regular；行内粗体、斜体遵循所在标题/正文的字号，嵌套强调保留各自语义。任务标记为 12 pt，独立 16 pt 槽，与第一行文字基线对齐，不渲染成可编辑表单；条目间 10 pt，可正常换行。代码为 13 pt 等宽，使用轻底色、1 pt 分隔和 8 pt 圆角；标示代码语言，长行局部横滚。引用使用一条细竖线和 16 pt 内缩，不加引用卡片或装饰引号。表格为 14 pt，单元格内边距 12 pt，轻底色表头、水平分隔和 Markdown 对齐方式；长表格局部横滚。

数值集中于 `tokens.json` 的 `readingMetricsPt` 并生成 MeltedReading。两种外观共享结构，复用现有语义色；共享 Markdown 包供后续 iOS 使用，移动端的 Dynamic Type、44 pt 操作区仍须在 iOS 实现时适配和验收。浏览器参考页保留交互方向与同步 token；本次细节以[原生阅读验收](validation/2026-10-15/reader-refinement.md)为准，不将旧参考页当作像素级实现。

## 6. 状态与微文案

| 语义状态 | 示例文案 / 操作 | 呈现规则 |
| --- | --- | --- |
| 首次无内容 | “添加一个来源，或导入想整理的内容。” | 一个主要入口，另一个轻量次入口 |
| 正常无变化 | “这次没有需要你关注的新内容。” | 安静留白，不补无关推荐 |
| 处理中 | “正在整理内容…” | 小型进度；未知时长不造百分比 |
| 局部来源失败 | “部分来源暂时无法更新。” / 查看详情 | 保留可用内容，说明覆盖缺口 |
| 离线有缓存 | “已离线。最近更新于 14:20。” | 紧凑状态条，原内容可阅读 |
| 模型/配额不可用 | “暂时无法整理新内容。” / 查看原因 | 提供用户可执行动作，技术日志放详情 |
| 内容存在矛盾 | “关于这一点，来源说法不同。” | 在对应内容旁标注，不只改颜色 |
| 更正 | “这条内容已更正。” / 查看更改 | 保留原阅读位置与版本入口 |
| 保存失败/版本冲突 | “偏好尚未更新。” / 查看变化 | 保留用户编辑，不清空表单 |

避免“智能洞察已就绪”“AI 正在深度思考”等泛化文案。明确实际发生的动作、受影响范围和下一步。不用 toast 承担关键错误，也不每次重试弹窗。

## 7. 原生行为、无障碍与动画

2026-10-15 品牌与列表调整：使用原创的连续圆润小写 m，矢量源在 `assets/brand/mark.svg`，生成同源 Swift Shape 与 README 亮暗标识；状态栏使用 18 pt 图标槽和现有 accent 色。列表选中反馈为 120 ms ease-out，只在选择变化时触发；已选行重复点击直接返回。分类标签不单独接受按压/悬停手势，减少动态效果时关闭行内自定义动画。其他区域的现有动画不受本次修改影响。

标准键盘命令包括 Command-F 搜索、Command-comma 设置、Command-plus/minus 阅读缩放、Command-0 还原、Escape 关闭暂态、Command-Z 撤销可撤销动作；用系统菜单提供并避免覆盖输入框行为。列表/详情返回遵循平台习惯，原生文本选择、复制、链接、上下文菜单保持可用。

macOS 使用系统控件尺寸；自定义小图标操作建议至少 28×28 pt 有效点击区并有足够间隔，这只是项目初始值。iOS 触控目标至少 44×44 pt，阅读与操作适配横竖屏、safe area 和最大辅助字号；不能把桌面尺寸直接套给手机。

VoiceOver 顺序为工具栏、筛选、列表、详情；图标按钮有动作名称，状态提供文本，内容章节有标题语义，表格有标题/列头。焦点进入/离开弹窗可预测，关闭后回原触发控件。hover 专属动作必须另有键盘/触控入口。

系统原生过渡优先；自定义反馈约 120–180 ms，区域切换约 180–240 ms，均是候选值。Reduce Motion 下取消位移/弹簧和非必要渐变；Reduce Transparency 下使用实底；Increase Contrast 下保留清晰边界。不做循环闪烁、装饰呼吸或持续滚动消息。

## 8. 组件清单与实现门槛

2026-10-15 原生界面修订：内容列表底栏与列表共用 `canvas`、语义分隔线和文字边线；Logo 在左，计数在右，不使用中性灰材质和竖线拼接。连接入口与服务器确认页共用 440 pt 内容宽度、32 pt 页边距、28 pt 分组间距和 40 pt 控件高度；小窗口可滚动，错误完整换行。品牌、说明、字段、主动作保持同一左边线，取消大圆形玻璃装饰、卡片阴影及重复图标。

2026-10-15 连接流程修订（用户指定）：连接入口与确认页共用一层缓慢流动的“融化”背景（低透明度暖褐色液滴，静置于内容之后，减少动态效果时静止），不叠在正文或阅读界面；移除“还没有服务器？”折叠说明和冗余提示文字；Wordmark 使用 SF Pro Rounded；入口内容按视觉中心略微上移；页面切换使用短距离滑动 + 淡入，品牌标识跨页连续；登录方式用分段选择器，信任确认用自定义勾选控件，均来自设计系统。

2026-10-16 位置与动效修订（用户指定，取代上一条的滑动切页）：Wordmark 放在连接表单列中、页面标题上方，与输入框左边线对齐；阅读工作台不显示 Wordmark，也不为它预留标题带，列表底栏只保留计数与加载状态。连接步骤只做短淡入淡出，取消表单和按钮的位移、弹簧与错峰入场；切换登录方式也不插值表单高度，避免按钮跨位置飞动。背景自身的缓慢流动保留，减少动态效果时继续静止。

现有 macOS 源码按 App、State、Connection、Library、Reading、Search、Settings 拆分；视图只消费状态与动作，凭据和网络留在 MeltedCore。具体依赖方向见 [客户端工程说明](../apps/macos/README.md)。tokens.json 新增连接页和底栏尺寸组，生成 Swift token，禁止业务页面另建色板。

建立 MeltedDesignSystem（Swift package）统一语义 token 和可复用内容组件：ContentToolbar、FilterSelection、ContentRow、ReadingDocument、EvidenceDisclosure、ContentStatus、FeedbackActions、PreferenceDiff、SourceHealthRow、ConnectionBanner、EmptyState、SettingsEntry。原生 Button/List/Form/Toolbar/Sheet 不另造一套。不要把 token 数值散布到业务 View。

组件都有默认、hover（适用时）、pressed、selected、focus、disabled、loading、error；按实际用途覆盖，不给每个静态组件造八种状态。异步操作在状态机确认前不显示成功。界面错误使用本地化短文案与恢复动作，诊断 ID 可复制。

## 9. 质量验收

先建立所有页面、sheet、popover、菜单和空/加载/异常状态清单，再按变更范围检查。新增设计系统组件须在独立原生组件预览页和实际页面验证，不能仅用浏览器参考页。

最少覆盖浅/深色，最小/初始/全屏窗口，最小支持系统与当前支持系统，阅读 200%、中文/英文、键盘与 VoiceOver、Reduce Motion/Transparency、Increase Contrast、系统强调色、活动/非活动窗口。iOS 开工后加入实体设备、Dynamic Type 最大档及横竖屏。

颜色或共享组件调整时对照四个基本设计组合；用同一内容检查状态、层级和视觉一致性。手机还需检查小屏、safe area、长标题和 44 pt 操作区，不能以桌面窄窗代替移动端设计验收。

长正文（例如 5 万字）、表格、代码、图片、引用、导出/许可长文和空/异常数据均需真实渲染；不能只看 SwiftUI Preview 或缓存截图。保存构建标识、系统、窗口尺寸、主题/辅助设置、截图、AX/操作结果和未通过项；截图中隐藏真实私人内容。

阻止交付的问题：裁切/遮挡、重要文字不可读、焦点不可见、关键动作只在 hover 可达、交通灯与 toolbar 冲突、错误显示成功、未知显示证实、点击动作无反馈、明显风格漂移。视觉评审检查层级、节奏、密度、对齐和材质是否服务内容，同时清理无语义圆点、拼接式元信息、重复眉题与泛化文案；自动对比值不代替人工观感判断。
