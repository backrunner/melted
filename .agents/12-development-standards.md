# Melted 开发规范

更新：2026-10-17。适用本项目的设计、实现、审查和发行。用户明确要求通用信息能力、先开源、原生高品质 UI；本文把已有架构转为可执行约定，不授权额外上线、外发消息或修改其他项目。

## 决策与文档

开始任务先看请求及实际工作树，再按变更读取相关设计。文档中的“建议/候选/目标”不是用户逐条批准的硬约束；在已授权范围内解决常规选择并记录理由，不为每次内部变更重复索要许可。只有确实缺少关键输入或存在外部/不可逆动作授权缺口才澄清。

产品范围见 01，架构/AI/API/插件见 02–05，平台见 06–07，UI 数值与规则以 11 为准；交付门槛见 08。改变公开契约、权限、保留期限、处理目的地或设计系统时同步相关文档和 ADR，避免互相复制大段规则。

先识别现有用户改动，保持任务边界；不为本任务丢弃其他未提交工作。提交/推送/部署按本轮已获授权完成；仅请求设计时不顺手实现或发布。提交信息描述实际问题和结果，不能写“全部验证通过”却只有编译结果。

## 代码与模块

TypeScript：handler 只做认证、解析和调用领域服务；业务规则不放在 HTTP 层或 provider adapter。外部 IO 使用 AbortSignal deadline/cancel，限制大小与并发；错误有稳定 code 和可追踪原因，日志不含正文/秘密。跨模块通过接口，事务边界明确，不在数据库事务中等待模型或插件。

服务端目录与依赖遵循 [工程说明](../server/README.md)：启动入口、HTTP、领域模块、存储适配和基础工具分开；按职责拆文件，不把无关能力合并为通用大文件。领域模块不得导入具体 PostgreSQL/Cloudflare 存储，两个存储实现互不依赖；共享校验放领域模块。新增或移动文件同时更新运行、打包、迁移与测试入口。

Node/PG 与 Workers/SQLite DO 共享契约测试，分别验证事务、所有权与恢复；本机后端调试只通过 Apple Container。具体入口见 [迁移与部署](15-typescript-transition.md)。

Swift：DTO、领域模型、视图状态、UI 组件分层。View 不直接访问凭据、执行 JSON 业务解析或承担重试流程；网络/缓存 actor 处理并发，UI 更新遵守 MainActor，绑定视图生命周期取消无用任务。只在必要的系统能力缺口使用 AppKit，保持原生行为和版本降级。

设计系统集中维护语义 token 和内容组件；原生控件优先。新增颜色、圆角、字体和交互模式先检查已有 token/组件，理由写进设计变更。窗口隐藏可见“资讯”标题，内容语义仍为资讯，不设导航侧栏，设置集中到标题栏最右侧入口；筛选并入标题栏，空间不足时收进面板，不恢复独立筛选条；用当前统一筛选模型承载 view/q/分类/标签/关注；时间等目标字段随真实契约扩展，手机与桌面语义一致。不把网页式 dashboard、装饰卡片或自定义窗口控件当默认桌面 UI。

品牌和阅读内容使用明亮暖纸白、极浅米白、暖灰与柔和褐色，不引入绿色或大面积偏暗米黄。亮暗主题成对维护，desktop/mobile 共用语义 token 与内容组件，分别适配原生导航和尺寸；macOS 视觉改动检查亮暗与窗口/字号；共享设计同时评审 iOS 亮暗目标，但未实现手机不能标为原生验证。整齐性通过共享布局约束实现：一致的文字边线、图标槽、列表节奏、表单和按钮基线；禁止用字符串空格或零散偏移补齐。放大字号后允许重排和增高，不为固定行高截断重要内容。

元信息按字段布局，避免用圆点、竖线或斜杠拼接一整行。未读以字重/AX 为基础，避免冗余状态点；当前列表仍有点与收藏图标，作为已知差异记录。分类胶囊用于列表/可操作条件，详情元信息为普通字段，标签不加井号串或重复徽章；标题、字重、间距和对齐负责层级。减少重复分类、泛化 AI 文案和无操作含义的图标；真实加载、错误、原生窗口控制及辅助功能状态仍需准确呈现。具体规则以 11 的“排版与信息克制”为准。

依赖引入前确认许可、平台支持、维护和替代成本；锁定版本、更新清单。不要为单个简单功能引入大框架。TypeScript/Swift 以真实 package/锁文件和工具链为准；MeltedKit 和 macOS 已有源码与检查入口，不沿用“仓库为空”的历史状态。

品牌位于连接表单标题上方；列表底栏左侧使用同源的紧凑字标，条数/加载状态靠右；外观设置可关闭整条底栏，默认开启并持久保存，关闭后不留占位。工作台顶部不另加品牌条。连接切步只淡化，方法切换不插值表单布局；业务状态不继承全局 spring。新增组件先查 [资源与组件索引](design/README.md)，数值变更同步 token、生成器与原生检查。源码能力与文档不符时记录缺口，尤其不能因有 SearchPalette 文件就声称搜索链路可用。

## 契约与状态

首个版本尚未发布，当前只维护一套契约和实现。删除过时输入别名、旧客户端/描述符回退和旧数据转换，不为未发布版本增加兼容桥。保留明确的版本校验、未知能力拒绝和当前 schema 的初始化/事务机制；不自动删除开发者已有数据库或凭据。

OpenAPI/JSON Schema 是共享契约源头，TypeScript/Swift 通过共享 fixture 验证。当前 OpenAPI 为已实现 development subset；04 的其余接口仍是目标，不把整篇草案当已冻结 v1。字段区分缺省/null/空值，标注时区、金额单位、语言、大小限制、枚举降级和版本。服务器/客户端未知状态显示未知，不能兜底为成功。

HTTP mutation 幂等、实体版本冲突、持续同步游标和任务状态按 02/04 实现；先测试失败/恢复语义，再优化吞吐。至少一次执行不等于恰好一次外部调用；超时可能已计费或已交付，不能无条件重发产生副作用。

API 测试包括所有权与跨账户负例；队列测试包括崩溃、租约、迟到结果；同步测试包括提交乱序、cursor 过期、快照翻页和离线 mutation；数据库测试覆盖当前 schema 初始化、幂等重放和中断恢复。根据受影响边界选检查，不让小文案修改跑全系统耗费验证。

## AI 和通用信息

信息来源/媒体类型/内容主题独立。Subject 可选；非技术内容不走二等路径；事实、观点、自述和创作按性质处理。主题、模板和 rubric 可配置，不用 if/else 特判第一个演示领域。

模型产物全部 schema 校验，带 model/rubric/pipeline/policy version；已知计算和权限由代码执行。决策分布不能转换为真相保证；引用存在和语义支持分别检查。保留失败、partial、unknown、conflicting 和过期证据状态。

用户显式偏好优先，反馈可撤销，学习不增加权限/处理目的地。新目的地必须有有效同意；fallback 不能越过数据去向限制。真实 provider/语料评测记录成本、样本、漏报和质量，mock 只证明控制流。

## 安全与数据生命周期

账号和凭据按服务器/账户隔离，provider/source key 留服务端；App 的 bearer 不交给正文、模板或插件。HTML 是受控静态正文，不是客户端运行时。服务端和客户端都执行相关校验，不能相互假定对方可信。

公开抓取与用户主动选择内网服务器是不同边界。URL、附件、callback/webhook 和插件网络执行 02/05 的 SSRF/限额规则；实际 egress 隔离不是 manifest 字段。插件只拿最少数据和所需 secret，不能直连整个数据库。

删除/撤销先阻止新任务、旧任务提交和外发，再清理附件、索引、记忆、设备和渠道；失败可观察。备份恢复继续执行删除记录。自托管管理员有机器权限，不宣传服务器看不到明文。

## 验证与证据

每个修改给出适当证据：代码/契约审查、自动测试、真实服务运行、真实模型评价、原生窗口/AX、签名/公证、远端 CI、实机 APNs、Apple 审核分别记录。没有执行就是未验证，不把预览/模拟器/编译成功提升为更强证据。

UI 变更按 11 的页面与状态矩阵验证；纯设计交付只报告 token/链接/示例检查及视觉参考检查，原生验证明确待实现。模型/平台外部资源不可用时，完成独立可做部分并准确列出缺口，不用合成成功填补。

建议验证记录放 `.agents/validation/`，写具体构建/日期、场景、结果、证据路径和限制；真正产生记录时再创建文件，不预造通过报告。隐私内容脱敏，真实截图仍应保留足以判断布局的内容。
