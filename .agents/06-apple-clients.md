# macOS 客户端与 iOS 预留

## 原生架构

首期 Swift + SwiftUI，必要时 AppKit 处理菜单栏、窗口与系统行为，URLSession 调 API，Keychain 存账户秘密。最低系统版本建议 macOS 14；iOS 后续建议 17 起，最终以用户覆盖和实际 SDK 验证决定，不先锁定具体 Swift/Xcode 版本。

视觉、组件和交互执行 [11-ui-design-system.md](11-ui-design-system.md)，开发遵守 [12-development-standards.md](12-development-standards.md)。新增 MeltedDesignSystem 包共享语义 token 和内容组件；系统控件外观与 API 按运行系统适配，不能因新 HIG 外观要求提高最低系统版本。

抽出 MeltedCore（协议 DTO、认证、同步、离线操作、偏好）和 MeltedRendering（内容模型、Markdown、安全 HTML）。业务状态不依赖 AppKit；iOS 复用逻辑，单独设计导航、生命周期和通知，桌面以内容列表/详情双窗格阅读，手机使用列表到详情的导航。

desktop/mobile 从设计阶段共享 MeltedDesignSystem 的语义色、字体层级、间距、图标家族、内容状态和文案。颜色以 11 / tokens.json 的亮暗成对资产为准：浅色明亮暖纸白，深色暖炭灰与略亮阅读面。外观默认跟随系统，设备端可选择浅/深色；不允许服务端模板改变 App 外观偏好。手机使用根列表和详情 push、44 pt 触控区、Dynamic Type；桌面使用 集成筛选的标题栏/内容双窗格/快捷键。两端均无常驻导航侧栏，设置集中到标题栏最右侧入口。四种平台/外观组合共同评审；移动端设计预留不改变 iOS 后续实现的范围。

本地 SQLite 存缓存与待发送 mutation，建议通过成熟 Swift SQLite adapter；实施时确认库许可、维护及加密能力。macOS 明确文件权限和 FileVault/应用数据库加密的各自边界；iOS 单独配置适合生命周期的 Data Protection。不能仅因 Keychain 存 token 就宣称正文加密，也不能把两平台保护机制写成相同能力。

## 页面和状态

| 页面 | 用户要完成的事 | 必须有的状态 |
| --- | --- | --- |
| 服务器连接 | 输入地址、确认运营者/处理方、注册或登录 | TLS 错误、协议不兼容、邀请/关闭注册、失联 |
| 资讯工作台 | 浏览全部整理内容，用未读/收藏/分类/标签/关注/时间筛选 | 首次设置、处理中、筛选无结果、partial、离线缓存及覆盖提示 |
| 内容详情 | 按性质读消息/资料/变化，查看依据与版本修正 | 单一来源、未知、矛盾、来源失效、纠正历史、无需事实核验 |
| Subject | 描述目标、设置计划、即时获取 | 无适配来源、排队、运行、局部失败、预算不足、取消 |
| 偏好 | 写要求、看编译草案、确认、更改/撤销学习 | 冲突、编译失败、待激活、版本冲突 |
| 来源 | 添加授权来源、看最近更新/失败 | 授权过期、频限、不支持 pull、关闭 |
| 反馈记录 | 查看反馈怎样影响后续内容 | 待发送、待学习、已应用、已撤销、纠错中 |
| 导入内容 | 粘贴文本/链接、选择支持附件并提交整理 | 类型/大小不支持、上传中、已接收、整理失败 |
| 收藏与搜索 | 找到整理后的资料/消息 | 无结果、仅缓存结果、已删除/更正、分页 |
| 设置（唯一入口） | 兴趣与偏好/关注主题、来源与整理、外观、通知、反馈记录、账户/服务器/渠道和导出删除 | 多服务器隔离、权限拒绝、删除未完成、编辑冲突 |

服务端管理员的插件安装、密钥、网络权限、部署操作首期用 CLI，不挤进所有用户的日常阅读设置。普通用户仍可看模型能力与传输目的地，知道谁处理了自己的数据。

## 主要交互

主窗口无导航侧栏，采用集成筛选的标题栏 toolbar + 列表/阅读双窗格；窄窗与手机使用列表/详情切换。窗口隐藏可见“资讯”标题，默认“全部”内容，日期仅作分组。全部/未读/收藏快捷视图保留在标题栏；分类/标签/关注与文本搜索合并为 Spotlight 式统一搜索面板，不再使用独立下拉框，手机采用视图菜单和搜索按钮，避免换成多行工具栏。收藏在顶部快捷视图，分类/标签/关注在统一搜索面板；搜索与筛选取交集。空结果、清除、离线缓存范围及保留阅读位置遵循 11。设置按钮打开统一容器，表格中来源/偏好/反馈等是其内部页面，不是独立主导航入口。

内容元信息使用原生布局中的独立字段；分类和时间对齐，来源说明独立呈现，标签移到正文后的内容信息区。未读用字重和 accessibility value 表达，不用小圆点；收藏在详情动作保留明确文本。样式与文案执行 11 的克制排版规则。

MeltedCore 共享 FilterSelection（view/query/category IDs/tag IDs/subject IDs/time range/sort）和查询状态。查询变化取消旧请求；返回结果必须匹配当前 query hash，避免迟到响应覆盖。实体缓存与筛选结果分离，切换筛选不复制正文，服务端 cursor 不能跨查询混用。收藏取消后从当前收藏视图移除，保留可撤销反馈。用户显式选中主题后“立即获取”在列表结果摘要旁；主题管理与计划配置集中到设置。
onboarding 先让用户写“想看什么、希望怎样整理”，不预选技术兴趣或强制选技术分类。可选主题模板覆盖新闻/公共信息、文化/兴趣、生活和工作，技术雷达只是一个示例。整理后的资料卡、消息卡和变化卡共用阅读体验，不强制用户创建 Subject。

按内容性质组织详情：事件变化显示事实/影响，消息保留正文与安排，资料显示整理提纲，观点保留作者。来源核验按钮可展开支持材料、时间、独立来源和缺口；影响理解的未知/矛盾/更正状态在正文附近可见，外部打开由用户触发。没有变化时不填充无关内容。

详情可见“有用”“反馈…”，后者提供少看/更多细节/有误；核验区也能直达“有误”。一次点击记录反馈，区别已保存在本机、服务器已接收和规则已应用。永久主题屏蔽或重大偏好变化显示可读 diff，允许撤销。关注主题的“立即获取”就在目标旁边，运行详情展示覆盖和失败。

命令菜单支持快速切换 Subject、搜索整理内容、手动同步。菜单栏仅显示新变化数和一键打开，不做会不断更新打扰的滚动信息窗。未读数按新的有用变化，不按摄取文章总数计。

## Markdown、HTML 与附件

Markdown 是默认格式，支持标题、列表、表格、引用、代码、链接、任务状态；raw HTML 默认禁用。完整 Markdown 语法需有测试 fixture，不能只依赖 SwiftUI AttributedString 的部分支持。可选择成熟渲染库或受控 WKWebView，保留结构化 content AST 供无障碍和其他渠道使用。

HTML 只支持用户启用后的静态模板：服务端 sanitize，客户端再限制 WKWebView。禁止脚本、事件属性、iframe、form、对象、任意导航、file URL、自定义 scheme、外部字体和可跟踪资源；CSS 限定允许属性和布局。默认关闭 JS，无 JS-native bridge，使用非持久 web data store、严格 CSP 和导航 delegate。开启 HTML 不意味着开启可执行插件。

图片只走授权附件代理/本地缓存，网络请求不直接加载原站跟踪图。使用受控自定义资源 handler 时须校验所有权和路径；不能把 API bearer 暴露给正文。外部链接仅允许用户明确触发的 http(s) 打开，显示目的地；远程附件有长度、尺寸和类型限制。

主题通过客户端注入允许的样式 token，验证深浅色、文本放大、表格横向滚动、代码复制、链接焦点、VoiceOver 阅读顺序。服务端模板不能隐藏安全/核验状态和纠正提示。HTML 校验失败回退同一 document 的 Markdown，并告诉用户格式未能呈现。

最低权限渲染：禁止正文发起任意导航/custom scheme；仅由 App 注册的附件资源 handler 可加载授权资产。系统权限/证据/通知状态置于原生外壳，不能由服务器 HTML 重画。Markdown 和 HTML 均从同一发布快照派生，未知格式显示可读 fallback 或明确不支持，不加载远程脚本补功能。

## 同步、通知与生命周期

前台/应用运行时 SSE 提示后拉 changes；后台降低频率，离线展示缓存和最近成功时间。指数重试有上限，断线不弹连续提示；恢复连通后重建变化。缓存只保留本人内容，不混合不同服务器。

反馈/阅读 mutation 先持久化，网络恢复幂等提交；来源、Subject 和偏好编辑遇到版本冲突须合并或明确重试，不能静默覆盖。注销撤销会话和设备，暂停 pending 操作；删除账户同时处理外部删除待办。

首期应用运行时可对刚同步的变化发本地通知，遵守用户设置；退出后不能承诺收到提醒。APNs 是后续独立里程碑，拒绝通知仍正常阅读。默认普通更新进每日简报，急迫事件才单独提醒，有静默时间和每日限额。通知只显示通用更新提示，正文在认证 App 中拉取。

iOS 不依赖持续 SSE 后台连接；前台拉取、APNs 提示和系统允许的后台刷新协作。APNs 和后台刷新都不保证即时执行，最终一致性依靠变化日志；所有采集、持续推理和定时工作在服务器。

## 原生验收

验证真实构建的 macOS 窗口：最窄尺寸、放大字体、深浅色、全屏、键盘导航、VoiceOver、菜单栏、原生标题栏/交通灯、中文和英文。断网/恢复、休眠唤醒、服务器证书变更、token 过期、缓存迁移、多账户切换也必须运行测试。截图和 AX 证据来自真实 App，静态 mockup 不能作为已完成 UI。

外发建议 Developer ID 签名与公证、可复现版本及源码链接；初期手动更新即可。自动更新单独验证签名、回滚与 GPL 源码对应，不能为赶首期引入无验证的更新器。

### 服务器协商登录

连接页先输入服务器并获取 discovery，再显示运营者与处理声明。确认信任后，按服务器的 methods/preferred 展示账号密码、API Key、浏览器或身份密钥；单方法不增加选择步骤，多方法用原生 Picker。新方式没有适配器时提示不支持；切换方法/服务器清除输入秘密。密码和 API Key 不保存，成功后只把会话保存到本机钥匙串。
