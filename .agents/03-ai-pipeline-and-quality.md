# AI 处理、求真与偏好学习

## AI Native 的实现边界

程序负责执行、权限、配额和状态；模型提供语义判断、提取与整理。所有阶段产物可追溯，不让一个超长 prompt 同时决定采集、过滤、真实性、记忆与推送。

流水线与主题无关，不能只按技术新闻设计。先识别材料性质：事实陈述、观点、个人记录、通知、资料或创作，再选择适用的抽取/核验方式。客观陈述求证；观点保留作者和语境；个人记录保留自述属性；创作不当作事实报道。用户喜欢什么与内容是什么分别判断。

事件聚类只用于适合比较变化的内容；私人消息按来源、对话、发送者和时序保留边界，不因语义相似合并独立通知。主题标签可配置，不将模型 choice 固定为技术领域列表。Subject 可选，一般输入由全局偏好处理。

| 阶段 | 输入 → 产物 | 失败或不确定时 |
| --- | --- | --- |
| 接入检查 | envelope/附件 → 有效 receipt | 拒绝无效输入或隔离，保留错误 |
| 多模态归一化 | 原始媒体 → text blocks/时间轴/出处 | unsupported、partial 或重试；不编造转录 |
| 廉价去重与筛选 | 哈希、URL、文本 → 候选/重复引用 | 无 embedding 时用词法候选；不直接永久删除 |
| 内容提取与可选聚类 | 候选文本 → InformationUnit、适用 claims、可选 event revision | 结构无效则限次修复；不发布 |
| 个性化决策 | claims + 偏好 → 多维 judgment | 低确定性保留到待整理，避免悄悄漏掉重要内容 |
| 检索与证据核验 | 适用 claim + 限定来源 → evidence assessment | 明确 unknown/conflicting；非事实材料记录不适用 |
| 内容整理 | 可用事实、差异、偏好 → BriefingDocument | 禁止添加无支持的新事实；重新生成或留待处理 |
| 输出检查 | document + evidence → 发布版本 | 阻止伪造引用、混淆立场和 HTML 危险内容 |
| 交付与反馈 | revision → app/channel/feedback | outbox 重试；反馈独立保存，不因模型失败丢失 |

明确不相关或硬规则禁入的内容可在昂贵抽取前终止；边界候选保留到下一阶段。分类结果按问题维度复用，最终发送/合并/忽略由版本化策略代码合成。

## 多模态路由

检查实际文件类型、大小和时长，不信任扩展名/MIME 声明。每个 part 保留位置和解析状态。文本分块；HTML 去脚本、导航和营销组件；图像走 OCR 或 vision，识别文字与模型推断分别保存；音频先转录，证据带时间戳和可用的 ASR 质量信号。视频后续使用限量关键帧和音轨，不能称为完整画面理解。

示例默认上限（实施时调整、在能力接口公开）：JSON 1 MiB、每图 10 MiB/2000 万像素、音频 50 MiB/30 分钟、每条 8 个 part。超限明确拒绝或经用户同意分段，不能偷偷只处理开头。Jev 接收归一化文本与结构，不假设它支持原始音视频。

路由先检查传输授权，再检查能力、预算、时延和可用性。fallback 只能用已授权目的地，不能从本地模型静默切到云端。媒体 provider 不可用时可处理可用文本，但整条记录标记 partial，简报说明缺口。

## “降熵”变成可测试行为

这里降熵是产品表达，不声称计算信息论熵。操作包括去掉套话、合并同一事实、去掉无新内容的转载、保留数值与限定条件、对变化排序、将不同立场写成可比较陈述。

三级去重：payload/规范文本哈希识别完全重复；canonical URL、词法/可选向量找近似候选；语义判断确认同一事件及新增事实。不能只因主题相似合并。转载同一发布稿算同一证据家族，不增加独立佐证数。

新版本、安全修复、反转或新增限制形成 event revision/delta，不重复推送整篇旧摘要。错误聚类必须可拆分，并纠正受影响简报，保留修正历史。营销稿也可含真实价格和日期：抽取事实、标注利益关联、删除宣传包装，不自动屏蔽整个来源。

## 求真分成三层

1. 材料忠实性：引用是否存在，摘要是否保留数值、否定词和限定条件。
2. 证据支持程度：材料是否支持 claim，有无独立佐证、利益关联、过期或反证。
3. 现实核验范围：是否找到一手记录或独立佐证；未查到不能当作证伪或证实。

“某公司宣称性能翻倍”可以由发布稿支持；“实际性能翻倍”需要不同证据。模型记忆与自信不是外部证据。

claim 状态建议：`supported_in_material`、`corroborated`、`single_source`、`conflicting`、`unknown`、`outdated`。支持/反对记录分别保存，不压成一个真假分数。`corroborated` 要求独立支持及核验范围说明，仍不是绝对真理。

非事实内容的外部真实性核验标为 `assessment.scope=not_applicable`，不为了追求统一“truth 分数”把意见、感受或创作判成低可信。仍检查整理是否忠实、归属是否正确，混合内容按陈述分别处理。

用户可调核验深度、单一来源内容、来源权重和预算；不能让偏好覆盖证据状态。高风险内容限制为带出处的信息变化，避免无依据的行动结论。首期核验已接入来源和授权页面；额外搜索需要配置检索能力和预算，不能假定已搜索全网。重要但未确认的安全事件可作为“尚未确认的风险”呈现。

生成文档逐 claim 绑定 evidence ID；代码检查引用存在与授权，窄问题判断语境支持性。参考 [TypeSafe citation check](https://docs.typesafe.ai/cookbooks/citation_check) 的先匹配、再检查语境思路；其示例结果不能代替 Melted 领域验证。

## Jev 集成

TypeScript HTTP adapter 对接 `POST https://api.typesafe.ai/v1/systemone`，服务端保存凭据；发送 `state` 和 `questions`，答案映射回相同 ID。question ID 不传给底层模型，语义必须写在 instructions。依据 [TypeSafe API](https://docs.typesafe.ai/api)。下面是设计示例，尚未执行：

```json
{
  "model": "jev-latest",
  "state": {
    "item": {"text": "已报名的摄影工作坊通知：开课时间从周六改为周日"},
    "user": {"goals": ["关注摄影与本地活动，及时了解已报名活动的安排变化"], "excluded": ["没有具体信息的推广"]}
  },
  "questions": {
    "relevance": {
      "type": "score",
      "instructions": "item 对 user.goals 有多直接的影响？只依据所提供内容。",
      "criteria": ["无关联", "仅主题相关", "可能影响目标", "直接影响目标"]
    },
    "marketing_only": {
      "type": "noul",
      "instructions": "item 是否只有推广表述，没有可辨认的新事实？",
      "criteria": {"true": "只有宣传", "false": "含至少一个具体变化"}
    },
    "delivery_kind": {
      "type": "choice",
      "instructions": "依据 item 的时效和 user 的目标，适合什么处理方式？",
      "criteria": {"alert": "需要及时处理的具体影响", "digest": "适合简报", "hold": "信息不足", "none": "无关联"}
    }
  }
}
```

独立维度可合并一次请求，依赖结果的证据检索另走下一阶段。多标签用多个 Noul，不能用单选 Choice。Noul 是 yes 概率，无独立 confidence；Score 按 rubric 范围归一化，不能默认它就是 0–1。Choice/Score confidence 表示分布集中程度，不是事实正确性。依据 [TypeSafe Confidence](https://docs.typesafe.ai/confidence)。

保存原始分布、rubric version、实际 model ID 和成本。示例用 alias；生产选并记录可固定版本，升级先离线比较再灰度。通用生成模型可实现相同 Decision 接口，但须声明缺少相同校准语义，自报 confidence 不当作 Jev 等价分数。阈值通过本领域标注集标定，重大信息优先控制漏报，不用全局 0.8 阈值。

## 偏好、反馈与 mem

分别保存 ExplicitPreference、ObservedFeedback、LearnedPreference、CompiledPolicy。显式排除与传输边界优先，Subject 局部偏好其次；学习不能越过用户硬约束。

自然语言偏好编译成可读结构草案，校验冲突、预算和格式，用户确认后原子激活。明确目标的隐藏/少看反馈可生成受限补丁；模糊反馈不能自动变成永久屏蔽。“有误”进入核验纠错，不能解释成不喜欢话题。

反馈接收、规则应用和学习生效分开记录：received/queued 不代表 applied。确定的隐藏可立即更新本机；语义反馈需要生成补丁时保持待处理，生效响应带 policy version。一次点击不能先显示“已更新偏好”再在后台静默失败。无障碍文案和状态展示使用 [UI 规范](11-ui-design-system.md)。

反馈关联内容版本、策略版本、原因和 mutation ID；撤销追加反向事件。用户可查看学到什么、删除学习项、锁定显式偏好、关掉学习。临时关注有 TTL，不永久记忆。

首期内置 memory 存有来源的偏好条目及摘要，独立可用。外部 mem 只接收授权的必要摘要，不默认上传所有原文；条目有 owner、来源反馈 ID、期限和删除引用。服务停机回退内置策略，不能阻塞简报；读取不能恢复已撤销条目。

学习候选 policy 经 diff、硬约束和回放比较；用户开启自动学习时只有低风险调整自动激活，来源、传输和权限不会自动变化。探索区域可关闭且遵守排除；点击和停留时间不作为唯一目标。

任务固定 policy snapshot；发布前再次检查撤销/新硬性排除，冲突则取消或重算。纠错生成新 revision，并向已交付渠道发纠正事件。

发布结构化快照后再交付阅读内容，未经校验的逐 token 草稿不进入主信息流。对事件、资料、消息、观点分别选择内容结构，不能强制给所有材料生成“影响/行动建议”；可见证据状态由代码规则产出，模型和模板不能隐藏或美化它。

## 质量评价

授权材料跨新闻/公共信息、科学/文化、兴趣/生活、私人资料/工作消息和技术内容，覆盖中英文、转载、营销事实、矛盾、过期、图片文字、价格变化、ASR 噪声、否定句、prompt injection、来源不可访问。也纳入意见/自述/创作、静态资料与独立通知。按事件/资料组、来源、时间划分调参与锁定评测集，避免转载泄漏，并分别报告各领域结果。

测相关性 precision/recall、重大事件漏报、重复压缩、错误合并、引用存在、claim 支持、数字忠实、矛盾保留、unknown 表达、人工有用率和每份有用输出成本。压缩率不是质量。模型 judge 只辅助筛选，正式验收用人工标注与争议复核，报告样本量与局限；用户报错回流回归集。
