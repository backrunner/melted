# 产品与首期范围

## 产品承诺

用户描述“我需要了解什么、什么时候值得提醒、怎样整理”，Melted 交付符合这些目标的整理内容、有用变化及适当依据。用户不必逐个打开信息源、清理信息流、比较重复内容。

Melted 从首期起处理通用信息：新闻与公共事件、科学和文化、个人兴趣、生活信息、工作消息及用户提交的资料。这里的通用指内容领域开放，不代表首期支持每个平台或所有媒体编码。

首批向开源极客推广，利用自托管、开放接口和插件共建吸引参与者；他们可以用 Melted 处理任意关注领域。技术思维是工程方法，不是用户必须选择的内容范围。例如：

> 把我关注的新闻、摄影和本地文化活动整理成每天十分钟能看完的内容。保留具体事实和不同观点，去掉重复报道、营销套话和无关内容。工作消息中的时间变更单独提醒；没有值得看的内容就不用凑一份日报。

“对我的影响”属于分析，观点和个人感受应保持归属，不能强行改写成客观事实。静态资料可以整理成阅读卡，独立消息可以直接交付，不要求每条信息都是事件变化。没有新变化时可不生成简报；无需填满界面。

## 通用产品与推广入口

内容主题、来源/授权和媒体类型是三条独立维度。用户按自然语言描述主题，来源插件负责获取，模型按媒体能力路由；三者都不内置技术领域限制。默认分类与标签可由用户/服务端配置，不硬编码“技术栈、依赖、竞品”等专用结构。

用户无需先创建 Subject 才能接收和整理推送；全局偏好处理一般输入，Subject 为持续关注和主动获取增加局部目标。首期缩小的是连接器数量、媒体上限和部署复杂度，通用领域能力需要在首期验证。

交互和视觉执行 [UI 规范](11-ui-design-system.md)：内容优先、原生控件、克制色彩和清晰层级。默认入口是无侧栏的资讯工作台，窗口隐藏可见“资讯”标题，内容语义仍为资讯，以标题栏中的搜索/收藏/分类/标签/关注筛选组织全部内容，设置集中到标题栏最右侧入口，Subject 在 UI 中称“关注主题”；高品质阅读和异常状态属于首期验收范围。

## 将原始信息来源藏到阅读流程之后

建议把用户原意实现为“默认无需接触原始信息流”。主页只展示加工后的内容，详情可展开核验卡：发布者、时间、证据片段、独立来源数、矛盾和核验范围。外部原文跳转由用户主动触发。

不建议禁止查看来源。用户一旦发现错误却无法检查依据，信任和专业使用价值都会下降。这是待确认的产品建议，不是对用户原始要求的既定修改。

## 八项需求与交付范围

| 原始需求 | 首期建议交付（P0） | 后续增强（P1/P2） |
| --- | --- | --- |
| 减少切换和注意力浪费 | 统一资讯工作台、可选每日简报、变化卡片、限量阅读、低打扰提醒 | iOS、跨设备摘要、更多系统入口 |
| 标准化输入与智能路由 | 文本、Markdown、HTML、图文、音频上传；能力发现；异步处理 | 视频关键帧、复杂文件、实时流；不承诺任意编解码器 |
| 采集器与降噪、求真 | RSS/Atom、HTTP 推送、授权 URL 抓取；事件去重；证据核验 | 更多授权平台、跨源事件图谱、深度调查 |
| 任意标准服务器注册及 APNs | 自定义 HTTPS 地址、协议发现、注册策略；macOS 在线同步与本地通知 | 官方 APNs 中继；独立客户端直连 APNs；iOS |
| 自然语言偏好与输出格式 | 偏好编辑、可撤销反馈、Markdown；受限静态 HTML 模板 | 更多模板、复杂交互；不开放客户端脚本插件 |
| Subject 主动获取 | 即时和定时运行；向所有适配的已启用来源分发；覆盖报告 | 搜索服务、更多主动来源、智能调度 |
| mem 与动态偏好 | 内置可解释偏好记录、版本化学习、可选外部 memory 适配器协议 | 指定 mem 服务的正式适配与长周期评价 |
| 服务端其他能力插件化及独立输出 | collector/provider/stage/memory/channel 类型；首批参考插件；签名 webhook 输出 | 插件目录、邮件/聊天渠道、团队服务 |

P0 图像和音频处理是受能力与配额约束的真实链路：至少配置一个能处理图像的 provider 和一个转录 provider；没有对应能力时返回明确的不可用状态，不能静默当作成功。视频、长音频和特殊媒体全覆盖建议延期，需要确认。

## 首期闭环

1. 运营者部署服务端、设置模型与来源，生成邀请或开放注册。
2. 用户在 macOS 输入服务器地址，查看运营者、数据处理去向并注册。
3. 写一句偏好，启用至少一个来源或提交内容；可从通用模板开始，也可自行定义 Subject。
4. 服务端接收、解析、按需聚类、过滤、执行适用核验，再输出消息/资料或简报。
5. App 展示变化、事实与分析、核验边界；用户反馈“少看此类”“需要更多细节”或“有误”。
6. “隐藏这条”等确定操作在本机立即反映，服务器接受后才算跨设备生效；涉及规则变更的“少看此类”若需要语义解释，先显示已记录，规则准备好再显示已应用。自然语言改动展示草案。隐式学习在约束内生效，可查看、暂停和撤销。
7. 定时或主动运行 Subject；同一服务端也能向 webhook 交付，不依赖官方 App。

## P0 建议排除

排除社交公共广场、自动执行交易/购买、代用户对外发消息、无限滚动推荐、完整插件市场、复杂团队权限、商业计费、iOS 实现和通用自主浏览器代理。反馈不会自动订阅新来源、增加外部传输目的地或扩大插件权限。

采集插件不承诺绕过登录、付费墙、平台限制。首批使用 RSS、开放接口和用户授权内容；源不可获取时报告缺口。

## 产品质量与成功指标

主指标：用户每周完成的信息任务数、实际节省时间、重要变化遗漏率、简报有用率、每份有用简报的成本。日活、阅读时长、点击率只作辅助观察，不能主导推荐目标。

试用时记录同一 Subject 的手动基线和 Melted 工作流，并由用户核对漏掉的重要内容。比较应包括设定偏好、核验及纠错的时间。不要将压缩率直接解释为节省时间。

首批假设：每天一份 5–10 分钟可读简报；普通更新合并，重大变化按设置提醒；初始体验在部署完成、配置可用 provider 后 10 分钟内获得首份内容。这些都是产品目标，尚未测量。

## 角色和权限

服务端管理员安装插件、配置 provider、配额、网络权限与注册方式；普通用户管理自己的来源、Subject、偏好、设备和渠道。平台管理员不能通过普通用户 API 获得其他用户内容。自托管运营者掌握机器和数据库，仍可能读取数据；客户端必须明确这个信任事实。

首期一个账户属于一个服务器；macOS 可保存多个服务器账户，默认一次展示一个工作区。账户、证据和偏好均不跨服务器自动共享。
