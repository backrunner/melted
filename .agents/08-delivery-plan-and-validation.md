# 交付拆解与验收

## 当前交付状态

当前已实现 TypeScript 双后端与 Swift 阅读/鉴权链路，具体以 [实施记录](14-implementation-status.md) 和带日期验收为准。下面是完整产品的后续目标，不代表已实现。

用户已经确认处理通用信息、首批向开源极客推广，先纯开源。首期不实现商业计费；成本账本用于限额与观察，不用于收费。

## 每个里程碑的具体交付物

M0：需求映射、OpenAPI、plugin schemas、InformationUnit/BriefingDocument schema、数据库关系、权限矩阵、样本授权记录、LICENSE/贡献决定、可复现 provider 配置清单。样本和模板从首期覆盖多个领域，避免只用技术新闻调参。将 [UI 规范](11-ui-design-system.md)落实为原生组件及页面状态原型，并根据真实阅读效果调整 token；[开发规范](12-development-standards.md)及 guard 纳入贡献流程。

M1：migrations、健康接口、CLI、Compose、注册与密钥生命周期、ingest receipt、附件回收、任务/日志、备份恢复脚本、CI 的 TypeScript 测试与类型检查。

M2：各类型参考插件、最小可工作 providers、corpus fixtures、每阶段版本/trace/cost、事件 revision、claim/evidence、输出 sanitizer、签名 webhook 和接收端参考例。

M3：真实可运行 macOS 构建、共享 Swift 包与 MeltedDesignSystem、缓存迁移、导入/阅读/筛选/关注主题/收藏/搜索/统一设置及其子页面全状态、离线操作、同步契约测试、无障碍及窗口证据。页面依赖的搜索、收藏、反馈处理状态、偏好草稿和处理方授权接口必须联调，不能以本地假成功替代。

M4：Subject run、来源覆盖、scheduler 幂等/夏令时测试、偏好 diff、反馈撤销、mem 删除、learning 开关与变更回放。

M5：release source/tag 对应、dependency/license 清单、签名公证记录、安装/升级/卸载文档、7 天持续运行、质量报告、匿名且自愿的用户试用记录。不开启默认内容遥测；纯开源用户可本地查看并主动导出脱敏诊断。

## 工程验收矩阵

| 场景 | 验收证据 |
| --- | --- |
| 反复摄取同一请求/不同 payload 同 key | 一个逻辑 item；冲突 409；长期 external_id 更新可追踪 |
| worker 在模型请求前后崩溃、租约超时、迟到结果 | 可重领；无重复发布；fencing 防覆盖；外部重复费用如实记录 |
| provider 429/鉴权失败/无效 JSON/成本未知 | 分别退避/阻断/限次修复；预算不会被无限释放；错误可见 |
| 多并发预算与取消 | 原子预留不超额；取消已提交请求的费用仍计入 |
| 某源失败或所有源失败 | partial/failed，不能说没有变化；有覆盖报告 |
| 筛选切换、旧查询迟到、取消收藏、分类删除 | 结果与计数属于当前授权查询；旧响应不覆盖新视图；空结果和离线缓存范围明确，返回保留筛选与位置 |
| 两个用户引用彼此附件/claim/token/Subject | 全部拒绝；日志不暴露对象详情；公开源缓存无私有泄漏 |
| 插件恶意 schema、巨量返回、私网请求、越权 secret | 隔离、超时/大小限制、egress 限制实际生效 |
| 恶意正文/HTML/prompt injection | 无工具执行、无越权网络、无脚本/追踪请求；生成不改权限 |
| 应用离线、cursor 过期、snapshot 分页期间变化 | 无遗漏、无重复；mutation 保留且冲突可解决 |
| 并发事务先分配低序号后提交、高序号先完成 | 同步游标不跳过任何已提交变化；稳定 snapshot 与后续 changes 无缝衔接 |
| 编辑偏好期间旧草稿完成、反馈尚未应用 | 保留编辑；按 base revision 处理冲突；收到/排队/应用状态与真实版本一致 |
| 偏好/来源撤销与旧任务并发 | 发布前校验；禁入内容不会被迟到任务重新发布 |
| 反馈、撤销、mem 停机/删除失败 | 正确版本；可回滚；外部失败待办明确；不丢反馈 |
| 用户删除、在途模型/插件任务与备份恢复 | deletion generation 拒绝迟到写入/发布；附件/密钥/记忆/渠道清除；恢复后 tombstone 仍生效；已发外部请求限制可见 |
| webhook 超时重试/内容修正 | delivery ID 去重；纠正能传至参考接收端 |
| scheduler 多实例/停机/夏令时 | slot 唯一；补跑合并；重复时间只一次 |

## 质量门槛（候选目标）

锁定至少 300 个不同事件/资料组样本，至少 50 个用户标注的重要信息，涵盖新闻/公共信息、科学/文化、兴趣/生活、私人资料/工作消息和技术内容，每组领域至少 40 个样本。覆盖两种语言、转载/相近不同事件、矛盾、媒体、错误源、意见/自述和无需事件聚类的内容；同事件/资料组全部材料同一 split。样本规模只是起点，不足以证明跨领域总体质量。

- 重要信息 recall 目标 ≥95%；同时报告 precision、实际漏报及各领域表现，不能只把所有内容放行来达标。
- 人工评判发布事实的证据支持率目标 ≥95%；对未知/矛盾正确标注，不能以过滤难例提高成绩。
- 引用 ID/片段有效性和关键数字拷贝的确定性 fixture 必须全部通过；语义支持另外人工评估。
- 重复输出目标减少 ≥80%，独立事件误合并目标 ≤2%；这两个指标一起看。
- 重大事实反转用例全部触发修正；用户偏好更新/撤销用例全部生效。
- 意见/自述不被改写成客观事实，创作不被误当新闻，独立消息不因相似被误合并；这些边界 fixture 全部通过。
- 首批用户对实际简报的有用率目标 ≥70%，配合漏报复核和时间对照，不以点赞代替质量。

阈值均为待评审目标；报告样本量、误差、model/prompt/pipeline version、成本与失败分布。合成测试只用于故障与安全，不代替真实信息的质量评估。

## 性能、运行与平台证据

参考容量假设：2 vCPU/4 GiB、5 用户、每日 1000 条短文本；测量前不能声称可支持更大规模。目标：不含模型的 API p95 <250 ms；空队列短文本从接收到可读目标 <90 秒（指定 provider 条件下）；长媒体单独报告。预算超限应暂停，不为满足时延绕过模型/核验。

7 天持续测试记录 CPU/RAM、队列最老年龄、错误率、实际模型费用、媒体磁盘增长、采集延迟和备份恢复耗时。并发压力先验证任务恢复与预算正确，再讨论吞吐量。

macOS 用真实 Release App、真实窗口/AX、深浅色/窄屏/字体/菜单栏/键盘/休眠/网络变化验证。Docker/Linux amd64 与 arm64 安装都需真实运行；交叉编译成功不等于双架构运行通过。

UI 详细矩阵以 [UI 规范第 9 节](11-ui-design-system.md#9-质量验收)为准，包括 200% 阅读字号、系统强调色、增强对比/减少透明与动态效果、最小及全屏窗口、长文和许可文本。记录构建与系统版本，实际点击、键盘和 VoiceOver 的结果与截图一起保留。HTML 参考页只验证视觉探索和自身交互，不替代原生验收。新增工作包和原生质量投入须在 M0 后重估，上述人周仍是初始粗估。

共享配色/组件设计阶段就对照 desktop/mobile 的亮暗四种组合，采用同一内容和语义状态检查一致性。手机参考纳入设计基线，实际 iOS 运行验收仍属于 P1；不能以手机形状的网页或桌面窄窗代替真实 iOS。原生实现默认跟随系统主题，并验证手动主题选择、大字号、安全区与触控尺寸。

APNs 将来单独验证开发/生产 entitlement、真实设备 token 注册、通知权限拒绝、token 失效、静默时间、退出与后台行为、中继停机/撤销。模拟器或 API 200 不能证明实际送达；内容同步和通知送达分开记录。

## 开源发布节奏

先内部 dogfood，再 10–15 位愿意反复反馈的设计伙伴，再公开 alpha。每阶段都记录失效场景和未完成范围。先发布一个可安装、可追踪、可纠错的版本，再扩张社区插件数量。
